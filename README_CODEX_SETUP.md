# KAIROS 0.4 — Codex Setup

This package contains the KAIROS v3 Phase 1A.2 source snapshot from commit `5b11b58fa4b6cb6ae4a5c1130ddfeecbda558e65`.

## Prerequisites

- Node.js `>=22.13.0`
- npm matching the selected Node installation
- Linux for the supplied bounded Sites scripts
- Bash and GNU `timeout`
- For `npm run install:ci`: `flock`, `curl` and `sha256sum`

No database, OpenAI key, Google credential or other production secret is required for Phase 1A.2.

## 1. Extract and enter the project

```bash
unzip KAIROS_CODEX_HANDOFF_0.4.zip
cd KAIROS_CODEX_HANDOFF_0.4
```

## 2. Install dependencies

The requested standard setup is:

```bash
npm install
```

For an exact lockfile install in a Linux/Codex environment, use either:

```bash
npm ci
```

or the repository's isolated, bounded install helper:

```bash
npm run install:ci
```

Do not commit generated `node_modules/` or `.sites-runtime/` content.

## 3. Configure the optional development login

`.env.example` lists the only application environment flag required by this snapshot and intentionally contains an empty value.

To enable the development/test authentication adapter locally, create an untracked local environment file and set the flag explicitly:

```bash
cp .env.example .env.local
```

Then edit `.env.local` to set `ALLOW_DEV_LOGIN=true`. Keep it false or unset when the development adapter must be disabled. The fixed development account is test-only and is documented in `KAIROS_CURRENT_BUILD_STATE_0.4.md`; it must not be reused as production authentication.

Never commit `.env.local`, API keys, OAuth credentials, tokens or cookie/session secrets.

## 4. Run the development server

```bash
npm run dev
```

Open the local URL printed by Vite/Vinext. The command keeps Wrangler logs within the ignored project runtime directory.

## 5. Run verification

Tests:

```bash
npm test
```

Lint:

```bash
npm run lint
```

TypeScript:

```bash
npx tsc --noEmit
```

Production build:

```bash
npm run build
```

The audited Phase 1A.2 snapshot recorded 42/42 passing tests. `npm test` intentionally invokes the production build before running `node --test tests/*.test.mjs`, so it takes longer than a source-only test command.

## 6. Start a completed build

After `npm run build`:

```bash
npm run start
```

The exact output directory is generated by Vinext and must not be committed or added back to the handoff package.

## 7. Optional Drizzle schema generation

The database layer is only an extension point in Phase 1A.2. Do not generate or apply migrations unless an explicit later-phase specification requires it.

If that specification exists, the current generation command is:

```bash
npm run db:generate
```

## 8. Expected boundaries

- `Search` in the Command Bar uses fixtures; `Navigate` is real; `Action` and `Ask KAIROS` are disabled previews.
- Dashboard records and charts use centralized development fixtures.
- DataGrid CSV/XLSX/PDF export is functional and selected-row-only.
- Image preview is functional over fixture files; PDF preview is simulated and is not a real renderer.
- Development auth is not production auth.
- D1/Drizzle files do not constitute a production database implementation.
- Phase 1B is not part of this source snapshot.

Before changing product behavior, read `00_KAIROS_MASTER_V3.md`, `KAIROS_CURRENT_BUILD_STATE_0.4.md` and `CODEX_HANDOFF.md` completely.
